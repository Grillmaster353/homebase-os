TERMINAL FIRST

At home on your Pi.

Use a 64-bit ARM64 Raspberry Pi or AMD64 Linux server on a trusted private LAN.

1. Copy the source

Download your repository's source and copy the unpacked folder to the Pi through your existing SSH/SFTP connection. If Git is already installed, clone the repository into a folder such as homebase-os.

2. Prepare Docker

Docker Engine and Compose v2 must already be installed. Their host installation is an explicit action you perform using Docker's official Debian guide for 64-bit Raspberry Pi OS. The app script does not install host packages.

uname -m
sudo docker compose version

3. Run the interactive setup

cd homebase-os
sudo bash scripts/setup-pi.sh

Enter the Pi's private IPv4 address and choose an administrator username. The hidden password prompt has no default password. Setup builds the image, prepares the account and TLS, then starts the authenticated HTTPS service.

4. Trust your own CA

Copy only homebase-rootCA.crt to your client devices over a trusted connection and compare its printed SHA-256 file hash. Import and trust it yourself in macOS Keychain Access or iPhone/iPad Certificate Trust Settings. Then open the printed HTTPS IP URL or persistent homebase-….local name.

Never bypass certificate warnings. The private CA stays outside the running dashboard's mounts. No public hosting, firewall rule or router forwarding is created.

PRIVATE BY DESIGN

Your credentials stay protected.
Your actions stay yours.

Salted scrypt passwords, protected session cookies, CSRF checks, rate limits, optional TOTP and AES-256-GCM credential storage form the local security boundary. The container runs without root or expanded capabilities.

Ask the assistant→Inspect the exact proposal→Approve once→Review the result

Manual TV buttons require approval by default. A paired direct TV can separately allow immediate buttons in its saved settings; assistant and automation proposals still wait for review.

Someone with access to the encrypted vault and its matching key can recover credentials. Protect the host and backups. A configured remote AI provider receives chat, selected telemetry and approved file-read contents; local Ollama inference can keep these on your own network.

ISP identification is optional and disabled by default. When enabled, the server checks api.ipify.org every 60 seconds for a public IPv4 change. It refreshes provider metadata through ipwho.is after an IP change, initial/error lookup or six-hour cache expiry. Both services see that connection's public IP; device inventory and integration credentials are not sent. The change-check IP stays in memory and is excluded from stored settings and API responses. Logo assets and manufacturer-prefix matching are local. This release has not undergone an independent security audit.

KEEP IT RUNNING

Simple maintenance.

sudo docker compose -f compose.yaml -f compose.lan.yaml ps
sudo docker compose -f compose.yaml -f compose.lan.yaml logs --tail=60

# Apply source updates without deleting data
sudo docker compose -f compose.yaml -f compose.lan.yaml up -d --build
The Pi's IP changed

Rerun setup with its current private IPv4. The existing account and CA are preserved and the server certificate is refreshed. Resume discovery on the intended network.

The .local name or a device is missing

mDNS and device advertisements need a multicast-capable LAN. Guest isolation, VLANs and sleeping devices can interfere. Use the certificate's direct IP URL and add authorized integrations manually when needed.

Keep data through an update

Keep the existing Compose project and named volumes. Never use down -v as an update command: it removes the saved account, encrypted vault and workspace. Protect backups and private CA material.

About this documentation website
